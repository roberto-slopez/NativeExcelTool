# NativeExcelTool alpha quickstart for Windows x64

This bundle contains optimized native binaries and two runnable sales reports. Each example constructs 10 fictional orders and calculates the period, total sales, unpaid balance, order count, and paid order count. The merged title and summary sit above a filterable Excel table at `A7:H17`. Total sales are **USD 1831.28**, with **USD 776.90** unpaid.

## Open the results immediately

Open `samples/orders-node.xlsx` and `samples/orders-dotnet.xlsx` in Excel or LibreOffice. These files were generated by the actual examples during release validation.

## Run both examples

Install Windows x64 Node.js 24, the .NET 10 SDK, and the latest [Microsoft Visual C++ v14 x64 Redistributable](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist). The native binaries import `VCRUNTIME140.dll`; the runtime may already be installed. Extract the entire ZIP before running the commands. Rust and Visual Studio build tools are not required to run this bundle.

From the extracted folder in PowerShell:

```powershell
./scripts/run-examples.ps1
```

The script generates and checks `output/orders-node.xlsx` and `output/orders-dotnet.xlsx`. It verifies the report header, frozen rows, table boundaries, typed cells, and matching values across both languages. Close an existing output workbook in Excel before rerunning.

## Node.js only

```powershell
$env:NATIVE_EXCEL_PROFILE = 'release'
node examples/node/export.cjs
node examples/node/export.cjs --table-only
# Optional destination:
node examples/node/export.cjs output/my-node-report.xlsx
```

Edit the `orders` array in `examples/node/export.cjs` to use your own data. The example imports the bundled native addon from `dist/release/index.cjs`; no npm installation is needed.

## C# only

```powershell
dotnet run --project examples/dotnet --configuration Release
dotnet run --project examples/dotnet --configuration Release -- --table-only
# Optional destination:
dotnet run --project examples/dotnet --configuration Release -- output/my-dotnet-report.xlsx
```

Edit the `Order[]` array in `examples/dotnet/Program.cs`. It uses `DateOnly` dates, `decimal` prices, `JsonSerializer`, and `NativeExcelNative.ExportAsync`. The project copies `dist/release/native_excel_ffi.dll` into its build output and includes the P/Invoke wrapper from `bindings/dotnet`. Keep the process architecture x64.

## Bundle contents and verification

- `dist/release`: CLI, C ABI DLL, Node addon/wrapper/declarations, Rust `.rlib`, schema, licenses, manifest, and per-file checksums.
- `examples/node` and `examples/dotnet`: runnable source examples with 10 in-memory orders each.
- `bindings/dotnet`: C# native interop wrapper.
- `samples`: the two generated Excel workbooks.
- `scripts`: example runner and independent XLSX verification.

The release includes a SHA-256 file for the ZIP. Compare it with `Get-FileHash <downloaded-zip> -Algorithm SHA256`. Rust consumers should integrate the crate from source; the `.rlib` requires a matching compiler and dependency graph.

This is an alpha before the release candidate. Live PostgreSQL/SQL Server integration, large-volume benchmarks, desktop interoperability certification, signing, and Linux/macOS packages remain pending. The two live database tests are intentionally ignored until trusted TLS connection strings are supplied. No RC or stable registry publication is included in this release.
